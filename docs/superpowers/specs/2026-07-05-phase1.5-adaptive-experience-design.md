# Phase 1.5：让游戏适配读者 — 设计文档

日期：2026-07-05
状态：已确认（用户批准）
前置：Phase 1 MVP（2026-07-03 设计文档）已合入 main

## 0. 背景与目标

来自用户真实游玩反馈（英文文章 "How OpenAI scales voice models" → 决策冒险）：

1. 场景假设了读者的领域知识，专业名词和情景设定看不懂；
2. 看不懂时没有求助途径；且"用户不懂什么"本身是最有价值的知识缺口信号，应该进知识库；
3. 英文文章被强制转成了全中文游戏，应遵从原文语言。

目标：游戏适配读者的语言与知识水平，并把"求助行为"变成第二类知识缺口信号纳入归档闭环。

## 1. 语言跟随原文

- **分析器**：prompt 增加语言检测；`KnowledgeProfile` 新增 `language` 字段（BCP-47 短码，如 `en`、`zh`）。分析产物（summary/concepts/takeaways 等）用原文语言书写。检测失败默认 `en`。
- **编译器**：游戏谱内容（intro/场景/题目/反馈/reveal/glossary）按 `profile.language` 生成。
- **UI 骨架不变**：按钮、页面标题等应用文案保持中文；变的只是游戏与笔记的内容语言。
- **归档语言统一英文**（用户决策）：
  - 英文原文 → 笔记/挑战卡天然英文，零额外成本；
  - 非英文原文 → 归档时用便宜模型把要点、错题解析、术语解释翻译成英文；关键术语保留原文对照，如 "connection pool (连接池)"；
  - 翻译失败降级：保留原语言归档，不阻塞归档流程。

## 2. 双轨求助机制

### 2.1 预生成术语表（零延迟、零边际成本）

- `GameSpec` 新增 `glossary: {term, explanation}[]`（可为空数组）。编译器生成时预判文章的高频障碍术语（5-15 条），解释用游戏语言、面向初学者白话。
- GameRuntime 在 scene/question/clueHub 节点文本下方渲染术语 chips；点击展开解释。
- **每次展开记录为一次求助**（kind='glossary'），同一局同一术语只记一次。

### 2.2 自由提问（兜底长尾）

- 每个节点固定一个「这里没看懂」入口：输入框 + 提交。
- `POST /api/hints`：请求 {gameId, nodeId, question}，服务端取该游戏的文章正文（截断）+ 当前节点内容作为上下文，调便宜模型实时回答（用游戏语言）。响应 {explanation}。
- **模型路由**：新增环境变量 `LLM_LITE_MODEL`（默认 `google/gemini-3-flash`），经 AI Gateway，与主模型 `LLM_MODEL` 独立；轻量任务（求助问答、归档翻译、术语卡干扰项生成）统一走它。
- 失败处理：接口报错时前端显示"求助失败，请重试"，不阻塞游戏进行。

### 2.3 求助记录（hints 表）

- 新表 `hints`：`{id, gameId, nodeId, kind: 'glossary'|'question', query（术语名或问题）, explanation, createdAt}`。
- **游戏进行中即落库**（不等归档）——中途弃局的求助记录也保留。
- 求助不扣分、不扣侦探模式的线索预算：学习行为不惩罚。

## 3. 难度

- 首页表单新增难度选择，`games` 表存 `difficulty`：
  - **beginner（默认）**：场景先用白话铺垫背景，术语随文解释，题目提供更多上下文；
  - **expert**：保持原文信息密度，节奏更快，铺垫从简。
- 编译器 prompt 按难度分支；glossary 两种难度都生成（expert 模式术语表条目可更少）。
- **中途换难度**：游戏页头部「换个难度重开」按钮 → `POST /api/games/regenerate` {gameId, difficulty} → 复用该文章已有知识档案，只重跑编译器（一次 LLM 调用）→ 新 game 行 → 跳转新游戏。原对局与其求助记录保留。

## 4. 归档闭环增强

- 归档时汇总该 game 的 hints：
  - 笔记新增「Knowledge gaps」段（英文，术语保留原文对照）；
  - **每条求助记录生成一张术语挑战卡**：question = "What is X? / 关于 X 的理解"式提问（选择题形式，正确项来自解释要点，干扰项由归档时的 LLM 调用一并生成），与错题卡同等进入 SRS 轮换；
  - 同一局中 glossary 与自由提问按 query 去重。
- 挑战卡（含原有错题卡）在非英文原文场景下由归档翻译统一为英文。
- Obsidian 导出包含 Knowledge gaps 段。

## 5. 数据与接口变更汇总

| 变更 | 内容 |
|---|---|
| `KnowledgeProfile` | + `language: string`（默认 'en'） |
| `GameSpec` | + `glossary: {term, explanation}[]`（默认 []） |
| `games` 表 | + `difficulty: text`（'beginner'/'expert'，默认 'beginner'） |
| 新表 `hints` | gameId/nodeId/kind/query/explanation/createdAt |
| 新 API | `POST /api/hints`；`POST /api/games/regenerate` |
| 环境变量 | + `LLM_LITE_MODEL`（默认 google/gemini-3-flash；求助/翻译/干扰项等轻量任务） |
| 归档器 | hints 汇总 + 术语卡生成 + 非英文→英文翻译 |

兼容性：已有 games/notes/cards 数据无 glossary/difficulty/language 字段——schema 均带默认值，旧数据照常可玩可看；旧游戏谱 `glossary` 缺省解析为 []。

## 6. 错误处理

- 语言检测失败 → 默认 en。
- glossary 生成为空 → 正常游玩，仅无术语 chips。
- /api/hints 失败 → 前端提示重试，不落库。
- 归档翻译失败 → 保留原语言归档并记录日志，不阻塞。
- regenerate 编译失败 → 沿用原有降级链（quiz 模式），再失败返回中文错误。

## 7. 测试策略

- 纯逻辑 TDD：glossary schema 校验、hints 去重与卡片生成、难度 prompt 分支路由、翻译降级路径（fake LLM）。
- 路由：hints 入参校验（zod）。
- 手测脚本：种子游戏增加 glossary 样例数据以便无 API key 验证 UI。

## 8. 非目标（YAGNI）

- 自适应难度（按求助频率动态调整）→ Phase 2+。
- 双难度谱预生成与进度映射 → 不做。
- UI 骨架多语言化 → 不做。
- 历史旧笔记回溯翻译成英文 → 不做。
